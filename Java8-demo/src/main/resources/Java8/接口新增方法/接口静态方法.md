# 介绍

> [!tip] 核心特性
> 接口静态方法是 Java 8 引入的新特性，允许接口定义静态方法，提供工具方法和常量。与实例方法不同，静态方法直接通过接口名调用，不需要实现类的实例。

接口静态方法的主要特点：
- 直接通过接口名调用
- 可以访问接口中的静态常量
- 不能访问实例变量或实例方法
- 可以与默认方法共存

# 简单使用

## 基本语法

```java
interface MyInterface {
    static void staticMethod() {
        System.out.println("静态方法");
    }
}
```

## 基本使用示例

```java
interface MathUtils {
    static int add(int a, int b) {
        return a + b;
    }
    
    static int multiply(int a, int b) {
        return a * b;
    }
}

public class Main {
    public static void main(String[] args) {
        int sum = MathUtils.add(5, 3);
        int product = MathUtils.multiply(5, 3);
        System.out.println("Sum: " + sum);
        System.out.println("Product: " + product);
    }
}
```

## 与默认方法结合使用

接口可以同时定义静态方法和默认方法，静态方法提供工具功能，默认方法提供实例相关的默认行为。

```java
interface Vehicle {
    void start();
    
    static void honk() {
        System.out.println("Beep beep!");
    }
    
    default void stop() {
        System.out.println("Stopping...");
    }
}

class Car implements Vehicle {
    @Override
    public void start() {
        System.out.println("Car starting...");
    }
}

public class Main {
    public static void main(String[] args) {
        // 调用静态方法
        Vehicle.honk();
        
        // 创建实例并调用默认方法
        Vehicle car = new Car();
        car.start();
        car.stop();
    }
}
```

## 接口常量

接口中定义的字段默认是 `public static final` 的，可以作为常量使用，静态方法可以直接访问这些常量。

```java
interface Constants {
    // 接口中的字段默认是 public static final
    String APP_NAME = "MyApp";
    int VERSION = 1;
    
    static void printInfo() {
        System.out.println(APP_NAME + " v" + VERSION);
    }
}

public class Main {
    public static void main(String[] args) {
        System.out.println(Constants.APP_NAME);
        System.out.println(Constants.VERSION);
        Constants.printInfo();
    }
}
```

# 最佳实践

1. **使用静态方法提供工具功能**：为接口相关的操作提供工具方法，避免创建单独的工具类
2. **保持静态方法简单**：静态方法应该提供简单、无状态的功能，避免复杂的业务逻辑
3. **避免过度使用**：不要将所有方法都定义为静态方法，只用于适合的场景
4. **与默认方法配合**：静态方法提供工具功能，默认方法提供实例相关的默认行为
5. **文档化静态方法**：清楚地记录静态方法的用途和使用方式
6. **命名规范**：静态方法的命名应该清晰表达其功能，遵循 Java 命名规范
7. **访问控制**：根据需要选择适当的访问修饰符，通常使用 public
8. **避免依赖实现细节**：静态方法应该只依赖接口中定义的常量和其他静态方法
9. **考虑性能**：静态方法在调用时不需要创建实例，性能较好，适合频繁调用的场景
10. **与其他新特性结合**：可以与 Lambda 表达式、方法引用等 Java 8 新特性结合使用
